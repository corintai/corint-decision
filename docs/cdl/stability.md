# CDL 稳定性与版本契约

当前语言版本 `0.1`、执行 Profile `cdl-core-risk-draft-1` 均为实验性。
本契约冻结支持声明的含义，不将现有版本改名为稳定版。

## 唯一能力来源

[capabilities.json](schema/capabilities.json) 是执行能力、入口、限制和证据的权威清单。
`status: supported` 仅表示该 Profile 中已有可执行证据；工具的
`implementation_status: implemented_in_declared_scope` 仅表示其 `scope` 已实现。
`experimental` 是成熟度，不能推断为“未实现”，也不能推断为生产认证。
`not_enabled` 是严格运行时的拒绝集合；创作期 import resolver 有独立 Profile。
`pending` 只列尚未实现的范围。单实例发布门禁已实现，多节点分发与跨宿主信任仍待实现。

## 独立版本轴

| 版本 | 决定什么 | 兼容规则 |
| --- | --- | --- |
| CDL `version` | 文档语法与核心语义 | 不支持的版本在编译前拒绝；不得自动降级 |
| Profile / capability ID | 当前目标允许执行的子集 | 新能力必须由目标显式声明；不推断其他入口支持 |
| 包、输入、Trace、反馈格式版本 | 各自序列化契约 | 分别校验，不能用 CDL 版本代替 |
| 引擎与 checker 身份 | 实际执行和验收程序 | 更新后重新编译并验证；旧证据不自动授权新程序 |
| repository revision / policy 指纹 | 源码闭包身份 | 改变源码、依赖或输入 schema 后重建对应证据 |

## 语义变更规则

修复违反已发布规范的行为，需要反例、回归测试和迁移说明。
改变合法策略的规定结果、默认值、类型或求值顺序，属于破坏性语义变更，必须使用新语言版本或新 Profile。
新增可选能力不得改变原支持子集的结果；扩展先独立验收，再更新能力清单。
删除字段、别名或公开错误码前应记录替代写法、影响范围和退出版本。
不得通过宽松入口、忽略字段或静默转换完成迁移。

## 稳定版候选退出标准

每项支持能力都必须具有完整依赖的成功、边界、失败及未执行路径证据。
文档和生成器中的支持例必须绑定同一份可执行资产；设计片段逐项登记范围。
Schema、解析器、编译器、执行器的职责分别验证，不能把 Schema 合法等同于可执行。
共享语义需要通过优化开关、Trace 开关与公开入口的等价性验证。
数字仍为 binary64；精确十进制、时间类型、数组等扩展不能隐式改变现有输入语义。
外部依赖、真实产品和容量验收分别报告。未配置环境不得计作通过。
